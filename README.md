# 文章 · 可复现材料

这个仓库放公众号文章里**读者能自己跑一遍的那部分**：脚本、汇总读数、复现步骤。
每篇文章一个目录，目录名 = 文章号 + 英文短名（不用中文，是为了链接复制到浏览器时不用处理编码）。

文章本身在作者自己的写作库里，这个仓库只承材料，不承载文章正文。

## 目录规则

- **一个文章号一个目录**，不合并、不拆散、不套多层。同主题多篇也各自一个目录。
- 每个材料目录里必有：`README.md`（环境 / 目录说明 / 复现步骤 / 口径声明 / 局限）+ 脚本 + `data/`（汇总读数）。
- **没有「拿去能跑」的东西的文章不进这里**——观点稿、纯论证稿、只引别人数据的稿子，一律不放。宁缺毋滥：
  为了凑「可复现」而把草稿包装成材料，等于给读者一个空头承诺。

## 怎么用

- 想自己跑一遍：进对应目录，按里面的 `README.md` 走。环境要求都写在那个 README 里。
- 只想看结果：直接看 `data/*.json`，那是汇总读数，不用跑。
- 想照抄实验：脚本是零依赖的（MCP mock server 用 Node 原生起，不用装包），改工具数那一个常量就能重跑。
- 材料有更新时作者会同步改这里，仓库有提交历史，能看每版改了什么。

## 口径与免责（读者先看这段）

1. **本地环境，不跨环境外推**。所有读数出自作者自己的 Mac（M5 Pro / 48GB + 本机 Ollama 0.34.1）。
   商业 API 侧的 prompt cache 跟 Anthropic / OpenAI 的 prefix caching 不是一回事，本文结论给的是**机制判断**（前缀一变后面全断），
   命中率数字不往别的环境套。
2. **耗时数字不进结论**。本机同时跑别的东西，同一配置两次能差一倍，要引的是 token 那一列。
3. **逐轮原始日志没放进来**。那种文件里带作者本机的目录路径（`~` 展开后的绝对路径），
   放上去既泄环境指纹、读者也用不上，所以只给汇总读数。
4. **脚本里的路径都是相对路径**，clone 下来在哪台机器都能跑，没有 `/Users/xxx` 之类的硬编码。
