# 汇总读数

这里放**跑完得到的汇总结果**，不是逐轮原始日志。

| 文件 | 是什么 | 对上文章哪一节 |
|---|---|---|
| `run1-summary.json` | 挂载成本矩阵（direct / codemode，n=1/3/5/10/20/40/60） | 第三节第一笔账 |
| `run2-summary.json` | 缓存实验主表（r1–r6 六轮，缓存命中与重算量） | 第三节第二笔账 |
| `run2b-lown-summary.json` | 加 nonce 版低 n 区（n=5/10）对照读数 | 第三节临界点那一段 |
| `cache-summary.json` | 缓存命中率汇总 | 第三节第二笔账 |

## 为什么只给汇总，不给逐轮

逐轮原始日志（`.jsonl`）里每一行都带**作者本机的绝对路径**（`~/.agents/skills/...` 这类），
放上去既泄环境指纹、读者拿到也没法用，所以只给跑完汇总成表的结果。

**想看单轮的**：把对应 runner 里的 `OUT_DIR` 指到一个空目录重跑一遍，它会自动写出逐轮文件，比下载别人的日志更干净。

## 数怎么用、怎么用错

- 可以引：文章里那两个结论数字（挂载 305 tokens/工具、缓存每轮重算 1.1 万量级）。
- 别拿来当压测报告看：这是**产品视角的小样本验证**，不是工程 benchmark，环境是作者本机 Mac + 本地 27B 模型。
- 别跨环境外推：商业 API 的 prefix caching 行为跟本地 Ollama 不同，机制相似不代表数字能套。
